# 定時処理の手順（Claude用）

1日7回（7・10・12・14・16・18・22時ごろ、日本時間）実行する。対象は Dropbox のアプリフォルダ「案件ノート」だけ。
道具は `python3 processor/dbx.py`（環境変数 DROPBOX_APP_KEY / DROPBOX_REFRESH_TOKEN を使う）。

## 守ること

- 案件情報は Dropbox のアプリフォルダと、作業用の一時フォルダ（実行後に削除）以外に書かない。
  GitHub、プロジェクトの記憶、チャットに案件の中身を書かない。
- カレンダーの書き込み先は「刑事弁護（claude登録）」だけ
  （id: `c_c9303302336e20d16aac02f9b0ffd9ac4fdbd43da7f14cfbf5091546b84fe55d@group.calendar.google.com`）。
- カレンダーの件名と案件カードには「案件番号 依頼者名」を使う（cases.json の client。先生の希望、2026-11-24。カレンダーは先生だけが見る）。
  フォルダ名は案件番号のまま（氏名を入れない）。このリポジトリには依頼者名を書かない。
- 法定期限と起案時間は自分で確定しない。下の「確認待ち」のルールに従う。
- 法的な検討をするときは Google ドライブの「刑事系論文書籍」フォルダを参照し、使った文献名を書く。

## フォルダ構成

```
/00_受信箱/                 アプリから届いた未処理メモ（.txt、先頭に案件・種類・作成日時）
/cases.json                 案件一覧（アプリが読む）
/先生からのお知らせ.md       案件に関係のない先生からのお知らせ・お願いの記録と、続けて守ること（Claudeが書く。アプリの「Claudeへのお知らせ・お願い」で表示）
/hidden.json                先生が「終了（非表示）」にした案件番号（アプリが書く。Claudeは書き換えない。ダッシュボードではこれらの案件を省く）
/ダッシュボード.md           全案件の今週の予定・期限・宿題・確認待ち
/判断の記録.md               先生の回答の蓄積（期限・起案時間の判断）
/案件/<案件番号>/            （試し案件だけ A000_TEST）
    案件カード.md
    case.json
    メモ原本/                処理済みメモをそのまま移す
    Claude成果物/
/処理ログ.md
```

## 手順

0. 毎回最初に `/先生からのお知らせ.md` を読み（無ければ何もしない）、「続けて守ること」と「一覧に入れない進行中フォルダ（終結案件）」をこの回の処理すべてに当てはめる。
   ここに載っている事件は、元のDropboxフォルダ（進行中事件）にあっても、cases.json への追加・「一覧にない」という指摘・進捗の声かけをしない。元ファイルは触らない。
1. `dbx.py ls /00_受信箱` で未処理メモを確認する。なければ 6（ダッシュボードの日付更新）だけ行う。
2. 各メモを読み、先頭の `案件:` で案件を特定する。`種類:` が「自動判定」なら本文から判断する
   （接見／依頼者との打合せ／期日メモ（公判・弁論準備など、期日当日の記録。次回期日と宿題を必ず拾う）／裁判所打合せ／検察官とのやりとり／面談（家族・関係者など）／電話／やるべきこと／確認待ちへの回答／その他）。
   - 「やるべきこと」は先生が自分で書いたToDo。1行ずつ案件カードの宿題に加え、締切が書いてあればダッシュボードの宿題にも載せる（期限の扱いは4のルールどおり）。
   - 「検討メモ」は先生自身の考え（方針・仮説・反論の筋・気づき）。ノート_検討メモ.md に貼るほか、案件カードの「弁護方針メモ」「検討すべき事項」に要点を（検討メモ 日付）付きで反映する。先生の考えを書き換えたり評価したりしない。
   - 「Claudeへの質問・依頼」は先生からの質問（例: この件どうなっていたっけ）や調べもの。その案件の案件カード・メモ原本（必要なら元のDropboxフォルダの資料）を読み返して答え、
     案件カードの「Claudeからの回答」（新しいものを上）と、ダッシュボードの「質問への回答」に日付・質問・答え・根拠（メモのファイル名）を書く。法的な調べものは「刑事系論文書籍」を参照する。わからない点は推測せずそう書く。
   - どの種類のメモでも、本文に先生がすること（「〜する」「〜を確認」「〜に連絡」「★」付きの事項、相手から頼まれたこと等）が書かれていれば、宿題（やるべきこと）として拾う。メモから拾ったものには「（メモから）」と付け、先生が不要と言えば消す。
   - 会務（先生の希望、2026-11-24）: 案件番号 B001〜、cases.json では `"crime":"会務"`、`client` に委員会・会議名。依頼者はいない。
     会議メモ（種類「会議メモ」）から、次回の会議日程・自分の宿題（担当・締切）・決まったこと・持ち越し事項を拾い、案件カードは「次回会議／宿題／決定事項／継続検討」の構成にする。
   - 執筆・研修準備・大学講義準備（先生の希望、2026-11-24）: 執筆は C001〜、研修準備は D001〜、大学講義準備は E001〜。cases.json では `"crime"` に区分名（執筆／研修準備／大学講義準備）、`client` に原稿・書籍名、研修名、大学・科目名。依頼者はいない。
     案件カードは、執筆なら「締切（原稿・校正）／構成・進み具合／宿題／参考資料」、研修準備なら「研修日・会場／締切（レジュメ提出など）／構成・進み具合／宿題／参考資料」、大学講義準備なら「講義日程（回ごと）／締切（資料・試験問題・成績提出など）／各回の内容・進み具合／宿題／参考資料」の構成にする。
     締切や研修日はカレンダーに登録し、起案時間の原則がない書面なので、執筆・準備の時間は案件ごとに先生に「確認待ち」で聞く。法的な調べものは「刑事系論文書籍」を参照する。
     法定期限の質問はしない。締切が書いてなければ「次回会議まで」として扱い、不明なら【要確認】。高山予定の照合は会議名（例: 刑事弁護委員会、刑事調査室）で行う。
   - 「お知らせ・お願い」（`案件: 全体`。先生の希望、2026-11-24）は特定の案件に関係のない連絡・指示。`/先生からのお知らせ.md` を get → 追記 → put で更新する:
     - 一番上の「続けて守ること」に、今後の処理で守るべきこと（やり方の希望・扱いの指示）を1行ずつ（日付付き）。前の指示と食い違えば新しいほうを残し、古いほうに「（○日の指示で変更）」と付ける。
     - 「一覧に入れない進行中フォルダ（終結案件）」に、終結・取込み不要と言われた事件名を1行ずつ（日付付き）。cases.json にある案件なら、先生の指示として hidden.json には触らず「お知らせ」に「アプリで終了（非表示）にしてください」と書く。
     - 「受け取った記録」（新しいものを上）に、日時・本文（先生が書いたまま）・Claudeがしたこと（1〜2行）・出典（ファイル名）。
     - ファイルが無ければ `# 先生からのお知らせ・お願い` と上の3つの見出しで作る。処理したメモは `/お知らせ原本/` に移す（8の代わり）。
     - 内容がある案件の話だとわかるときは、その案件の処理にも反映し、記録にその旨を書く。意味がはっきりしないときは推測で動かず、ダッシュボードの「確認待ち」で聞く。
   - `種類: 新規案件` なら `/案件/<番号>/` を作り、cases.json に追加する（本文の「依頼者名」を client に入れる）。
3. 案件の case.json と 案件カード.md を取得し（cases.json にあるのにフォルダや case.json がまだ無い案件は、ここで `/案件/<folder>/` と中身を新しく作る）、メモの内容で更新する。各項目に出典（メモのファイル名）を付ける。
   - 期日、法定期限、宿題、差入れ希望、検討すべき事項、関係者、手続の進捗、供述の時系列、示談、弁護方針メモ
   - 前の記載と食い違う内容（供述の変化、期日の変更）は「⚠ 変更」と書いて両方を残す。
   - 「次にやるべきこと」を最大5つ提案する。
   - 書式: 宿題（やるべきこと）は `- [ ] 内容（締切）`、済んだら `- [x]`。確認待ちは行の中に `【要確認】` を入れる。アプリはこの2つを数えて案件ごとに表示する。
4. 期限と起案時間
   - 先生が確認済みの基本ルール:
     - 勾留期間: 請求日を1日目に数え、末日が休日でも延ばさない
     - 控訴・上告の14日: 初日は数えず、末日が休日なら翌日まで
     - 起案時間: 意見書2時間、予定主張4時間、弁論3時間×2回、締切の3営業日前までに確保
   - それ以外の期限や、メモから日付が確定できないものは「【要確認】」として
     ダッシュボードの「確認待ち」に質問を書く（例: 「2026-012 勾留満期は12月3日でよいですか」）。
     メモに先生の指示があればそれを優先する。
   - 先生の回答（種類「確認待ちへの回答」）は案件に反映し、`/判断の記録.md` に1行追記する。
     アプリの確認待ちを押して書いた回答は「（質問）元の質問文」「（回答）先生の答え」の形で届く。質問文で該当する【要確認】を特定し、反映したらその【要確認】を消す。
5. カレンダー
   - 期日・確定した期限・起案時間を登録する。説明欄に `cn:<案件番号>:<項目キー>` を入れ、
     同じキーの予定が既にあれば新規作成せず更新する。
   - 起案時間は空いている時間帯（先生の「高山予定」と重ならない平日の日中）に「（仮）起案: 書面名」で入れる。
   - 既存予定の削除はしない。変更が必要ならダッシュボードの「お知らせ」に書く。
5-2. 進捗の声かけ（朝の回だけ。先生の希望、2026-11-24）
   - /hidden.json で非表示にした案件は除き、進行中の各案件の 案件カード.md を見て、先生に「これどうなってる？」と聞くべきことを選ぶ。例:
     - 宿題・次にやるべきことで、締切が近い／過ぎている、または2週間以上動きがないもの
     - 期日・期限が【要確認】のまま3日以上たっているもの
     - 相手のある事項（結果待ち・連絡予定など）で、1週間以上続報がないもの
     - 起案が必要なのに起案時間がまだ確保されていないもの
     - 最後のメモから1か月以上たっている刑事事件
   - 1日に多くて5件、急ぐ順に、案件番号と短い質問で書く。前日と同じ質問を毎日繰り返さず、3日答えがなければ「お知らせ」に1行残して間隔をあける。
   - ダッシュボードの一番上の「今日の確認」に書く。スレッドの返信では件数と「アプリのホームを見てください」だけ伝え、案件の中身は書かない。回答はアプリの「確認待ちへの回答」で受け取る。
5-3. 先生の予定の読み込み（毎回。先生の希望、2026-11-24）
   - 先生の「高山予定」カレンダー（list_calendars で名前から探す）の今日から60日分を**読むだけ**（書き込み・変更は「刑事弁護（claude登録）」以外にしない）。
   - 件名を cases.json の依頼者名（姓・名・「こと」の前後・事件名）と案件番号で照合し、刑事・民事・顧問など全案件の期日・打合せ・Ｂ会議・接見を拾う。
     同じ名前の案件が2つ以上あれば、どちらか【要確認】で聞く。関係のない予定（会議・研修・移動など）は載せない。
   - 拾った予定はダッシュボードの「今日・今週の期日」（14日以内、裁判所の期日は太字、3日以内は⚠）と、各案件カードの「期日」欄に「（高山予定より）」として書く。
     「裁判所の期日」は、裁判所が指定して裁判所（Web会議を含む）で行うものすべて。公判期日・判決期日・公判前整理手続期日・期日間整理手続期日・
     弁論準備期日・**打合せ期日**（裁判所との打合せ、「打合せ期日（web）」など）・進行協議期日・審尋期日・和解期日・口頭弁論期日など。件名に「期日」とあれば原則これに当たる（「期日候補」は除く）。
     太字は種類の言葉に付ける（例: `**打合せ期日**（web）`）。接見・依頼者との打合せ・会議は太字にしない。
     「刑事弁護（claude登録）」に同じ予定を重ねて登録しない。
6. `/ダッシュボード.md` を作り直す: 一番上に「今日の確認」、続けて 今日・今週の期日、14日以内の期限（近い順、3日以内は ⚠）、
   締切順の宿題、未対応の差入れ、確認待ち、お知らせ。
   /hidden.json の案件（終了・非表示）はダッシュボードのどの欄にも載せない（先生の指示、2026-11-24）。
   各行には必ず案件番号（A000・B001など）を入れる（アプリは、非表示の案件番号を含む行を表示時にも省くため）。
7. cases.json を書き出す。先生が取り込んだ案件（メモのまだ無いもの）も消さずに残す（形式: `{"cases":[{"id","client","initials","crime","custody","next","folder"}]}`）。
7-2. 種類別ノート（先生の希望、2026-11-24）: 接見・依頼者との打合せ・会議メモ・期日メモ・裁判所打合せ・検察官とのやりとり・面談・電話・検討メモ・その他 のメモは、
   `/案件/<フォルダ>/ノート_<種類>.md` の末尾に、前回の続きとして貼り付ける（古い順、ひと画面でざっと読める形）。
   見出しは `## 2026-11-24（火）11:20 接見` のように日時と種類。日時は先生が本文に書いた日付（「昨日の接見」等も含む）を優先し、書いていなければメモ先頭の `作成:`（送信ボタンを押した日時）を使う。本文は先生が書いたまま（誤字の直しや要約はしない）。最後に `出典: <ファイル名>` を1行。
   種類を自動判定した場合は見出しの後に `（Claude判定）` と付ける。やるべきこと・確認待ちへの回答・Claudeへの質問はノートに貼らない。
   ファイルが無ければ `# <案件番号> <依頼者名> <種類>メモ` で始める。上書きは dbx.py get → 追記 → put で行う。
8. 処理したメモを `/案件/<フォルダ>/メモ原本/` へ `dbx.py mv` で移す。
9. `/処理ログ.md` に日時・件数・登録した予定の件数を追記する（中身は書かない）。
10. 一時フォルダを削除する。
